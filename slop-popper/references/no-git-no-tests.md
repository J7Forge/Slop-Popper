**No git** (a plain folder or an unpacked zip):
- Unpack or copy it into a working copy and edit only that copy, never the original or the snapshot commit. The untouched original (for example the source zip) is the undo.
- Just before the first real edit (never in `--dry-run`), make a temporary repo whose git folder sits in a sibling folder outside the tree, and commit a baseline snapshot. From the tree, pass the paths on each command rather than exporting them: `mkdir -p ../<tree>.deslop` (in Windows `cmd`: `mkdir ..\<tree>.deslop`), then `git --git-dir=../<tree>.deslop/.git --work-tree=. init`, then the same prefix for `add -A` and for the commit, with a placeholder identity in case git has none set: `git --git-dir=../<tree>.deslop/.git --work-tree=. -c user.name=deslop -c user.email=deslop@localhost commit -m baseline`. If you do export `GIT_DIR` and `GIT_WORK_TREE`, unset them as soon as the run ends.
- Keep the git folder, `last-report.md`, and other deslop files in `<tree>.deslop/` so nothing gets packed, and never pack that folder. Once every review item is closed, delete only its `.git` folder. Keep `<tree>.deslop/last-report.md` (with the closed list and reject hashes) until the tree is replaced, so rejected items aren't flagged again and IDs aren't reused.
- `/deslop` and `/deslop-since` have nothing to scope by, so run as `/deslop-full`; the Pre-commit save point and re-staging don't apply.

**No tests:** add none in `/deslop`; in other modes, add focused tests where practical. If no tests cover a change, apply automatically only comment, import, and debug-output cleanup, plus renames and pass-through wrapper removals when every caller is in scope and the code still compiles, imports, or passes the type checker afterward. Hold everything else for review.
