# 9. Logging and debug slop
Output left behind from development or added for show.
- Look for: `print()`, `console.log`, `System.out.println`, or `dbg!` debugging calls; log lines that only say "entering function" or "done"; logging inside tight loops; logging secrets or full payloads; the same event logged at several layers; every log at the same level; chatty messages in logs, errors, or UI text: exclamation marks, emoji, or "Oops"-style phrasing (plain status text like "Saved" or "Order exported" is fine); `if __name__ == "__main__":` blocks or similar entry points holding demo or test code in modules that are never run directly.
- Fix: delete debug narration. Keep logs that help diagnose a real problem, such as a startup version line or a real error report, logged once at the right level (debug, info, warning, error) with useful context (IDs, counts, file names). Delete a `__main__` or demo entry point only when no docs, scripts, build files, or CI mention running that module; otherwise hold it for review. Rewrite chatty log and error messages to say plainly what happened; hold visible UI text for review.
